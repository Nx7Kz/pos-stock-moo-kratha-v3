# พจนานุกรมข้อมูล — ระบบ POS & Stock ร้านย่างให้หมูกระทะ บ้านน้องโฟค

ฐานข้อมูล **PostgreSQL 16** ชื่อ `pos_stock` — 13 ตาราง 3 view

## ความสัมพันธ์โดยรวม

```
users ─────────┬──< orders ──< order_items >── menu_items >── categories
               │      │                            │
               │      └──< payments                └──< recipes >── ingredients
               │                                                        │
               ├──< stock_docs ──< stock_doc_lines >────────────────────┤
               └──< stock_movements >───────────────────────────────────┘

dining_tables ──< orders
settings (คีย์-ค่า ตั้งค่าร้าน)
```

จุดเชื่อมสำคัญคือ **`recipes`** ซึ่งเป็นตารางสูตรอาหาร (BOM) ที่ทำให้ระบบรู้ว่าขายเมนูหนึ่ง
ต้องตัดวัตถุดิบอะไรบ้าง อย่างละเท่าไร

---

## ตารางข้อมูลหลัก

### `users` — ผู้ใช้งานระบบ

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `id` | SERIAL PK | รหัสผู้ใช้ |
| `username` | VARCHAR(50) UNIQUE | ชื่อผู้ใช้สำหรับเข้าสู่ระบบ |
| `password_hash` | TEXT | รหัสผ่านที่เข้ารหัสด้วย bcrypt |
| `full_name` | VARCHAR(120) | ชื่อ-นามสกุล |
| `role` | `user_role` | `OWNER` เจ้าของร้าน / `STAFF` พนักงาน |
| `is_active` | BOOLEAN | ปิดการใช้งานได้โดยไม่ต้องลบ |

### `dining_tables` — ผังโต๊ะ 20 โต๊ะ

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `table_no` | VARCHAR(10) UNIQUE | T01 – T20 |
| `zone` | VARCHAR(40) | โซนในร้าน (แอร์) / โซนนอกร้าน / โซนระเบียง |
| `seats` | SMALLINT | จำนวนที่นั่ง |
| `status` | `table_status` | `FREE` ว่าง / `OCCUPIED` กำลังใช้งาน / `BILLING` รอชำระเงิน |
| `sort_order` | SMALLINT | ลำดับการแสดงบนผังร้าน |

### `categories` — หมวดหมู่เมนู

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `code` | VARCHAR(20) UNIQUE | รหัสหมวด: `BBQ` หมูกระทะ · `SNACK` อาหารทานเล่น · `DRINK` เครื่องดื่ม · `ICE` น้ำแข็ง |
| `name_th` | VARCHAR(80) | ชื่อหมวดที่แสดงบนหน้าเว็บ |
| `sort_order` | SMALLINT | ลำดับแถบหมวดบนหน้าเมนู |

หน้าเว็บใช้ `code` เลือกไอคอนแทนรูปของเมนูที่ยังไม่มีรูป

### `menu_items` — รายการเมนูอาหาร

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `sku` | VARCHAR(30) UNIQUE | รหัสเมนู เช่น MN-B02 |
| `category_id` | FK → `categories` | หมวดหมู่ |
| `name_th` | VARCHAR(120) | ชื่อเมนู |
| `description` | TEXT | คำอธิบายสั้น ๆ ใต้ชื่อเมนู |
| `price` | NUMERIC(12,2) | ราคาขาย (`CHECK price >= 0`) |
| `unit` | VARCHAR(20) | ชุด / จาน / ขวด / ถัง |
| `image_url` | TEXT | รูปเมนู — `/media/samples/<sku>.jpg` รูปตัวอย่าง หรือ `/media/uploads/<sku>.jpg?v=…` รูปที่ร้านอัปโหลด · NULL = แสดงไอคอนหมวด |
| `is_available` | BOOLEAN | เปิด-ปิดการขาย (ปิดแทนการลบ) |

ไฟล์รูปเก็บที่ `backend/media/` ชื่อไฟล์เป็นรหัสเมนู ตอนเปิดระบบ backend ผูกไฟล์ใน `uploads/` เข้ากับ `image_url` ของเมนูรหัสนั้นให้อัตโนมัติ

### `ingredients` — วัตถุดิบในคลัง

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `sku` | VARCHAR(30) UNIQUE | รหัสวัตถุดิบ เช่น ING-M01 |
| `name_th` | VARCHAR(120) | ชื่อวัตถุดิบ |
| `grp` | `ingredient_group` | `MEAT` เนื้อสัตว์ / `VEGETABLE` ผัก / `DRINK` เครื่องดื่ม / `ICE` น้ำแข็ง / `OTHER` |
| `unit` | VARCHAR(20) | หน่วยนับ เช่น กก. ขวด ฟอง ถุง |
| `qty_on_hand` | NUMERIC(12,3) | **ยอดคงเหลือจริง** อัปเดตทุกครั้งที่มีการเคลื่อนไหว |
| `min_qty` | NUMERIC(12,3) | จุดสั่งซื้อขั้นต่ำ — ต่ำกว่านี้จะแจ้งเตือน |
| `cost_per_unit` | NUMERIC(12,2) | ต้นทุนต่อหน่วยล่าสุด (อัปเดตเมื่อรับเข้า) |
| `is_active` | BOOLEAN | ปิดการใช้งานวัตถุดิบโดยไม่ต้องลบ |
| `updated_at` | TIMESTAMPTZ | เวลาที่ยอดหรือข้อมูลเปลี่ยนล่าสุด |

`qty_on_hand` **ห้ามแก้ตรง** — ทุกการเปลี่ยนยอด (รวมยอดตั้งต้นตอนเพิ่มวัตถุดิบใหม่) ต้องผ่าน `stock_movements` เสมอ

### `recipes` — สูตรอาหาร (BOM)

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `menu_item_id` | FK → `menu_items` | เมนู |
| `ingredient_id` | FK → `ingredients` | วัตถุดิบที่ใช้ |
| `qty_per_unit` | NUMERIC(12,4) | ใช้กี่หน่วยต่อเมนู 1 หน่วย |

มี `UNIQUE (menu_item_id, ingredient_id)` — วัตถุดิบหนึ่งชนิดปรากฏในสูตรของเมนูหนึ่งได้ครั้งเดียว

## ตารางการขาย

### `orders` — บิล

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `order_no` | VARCHAR(24) UNIQUE | เลขที่บิล รูปแบบ `OD20260827-0001` |
| `table_id` | FK → `dining_tables` | โต๊ะ |
| `status` | `order_status` | `OPEN` / `BILLING` / `PAID` / `VOID` |
| `channel` | `order_channel` | `STAFF` พนักงานรับออเดอร์ / `CUSTOMER` ลูกค้าสั่งเอง |
| `guest_count` | SMALLINT | จำนวนลูกค้า |
| `subtotal` `discount` `service_charge` `vat_amount` `grand_total` | NUMERIC(12,2) | ยอดเงิน คำนวณใหม่ทุกครั้งที่รายการเปลี่ยน |
| `note` | TEXT | หมายเหตุของบิล (บิลที่ยกเลิกจะต่อท้ายเหตุผลไว้ที่นี่) |
| `access_code` | VARCHAR(8) | **รหัสโต๊ะ 4 หลัก** สุ่มตอนเปิดโต๊ะ ลูกค้าต้องกรอกก่อนสั่งอาหารผ่านมือถือ ใช้ได้เฉพาะตอนบิลยังเปิดอยู่ (เปลี่ยนรหัสได้) |
| `billing_at` | TIMESTAMPTZ | เวลาที่กดเช็คบิล ใช้เรียงคิวในแถบ "รอชำระเงิน" บนผังร้าน |
| `staff_seen_at` | TIMESTAMPTZ | เวลาที่พนักงานเปิดดูบิลล่าสุด — รายการที่ลูกค้าสั่งหลังจากนี้นับเป็น "ออเดอร์ใหม่" (ป้าย 🔔 + เสียงเตือน) |
| `opened_by` / `closed_by` | FK → `users` | พนักงานที่เปิดบิล / ปิดบิล (รับเงินครบหรือยกเลิก) |
| `opened_at` / `closed_at` | TIMESTAMPTZ | เวลาเปิด-ปิดบิล |

`channel` ตอนนี้เป็น `STAFF` เสมอ เพราะลูกค้าเปิดโต๊ะเองไม่ได้ (พนักงานเปิดโต๊ะแล้วออก QR + รหัสให้)
ส่วนการแยกว่ารายการไหนลูกค้าสั่งเองดูที่ `order_items.by_customer`

**ข้อบังคับสำคัญ** — partial unique index:

```sql
CREATE UNIQUE INDEX uq_orders_open_per_table
    ON orders (table_id) WHERE status IN ('OPEN', 'BILLING');
```

ทำให้ฐานข้อมูลรับประกันว่าหนึ่งโต๊ะมีบิลค้างได้ครั้งละ 1 ใบเท่านั้น

### `order_items` — รายการอาหารในบิล

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `order_id` | FK → `orders` | บิล |
| `menu_item_id` | FK → `menu_items` | เมนู |
| `qty` `unit_price` `line_total` | NUMERIC | จำนวนและยอดเงินของบรรทัดนี้ |
| `note` | TEXT | หมายเหตุต่อรายการ เช่น "ไม่ใส่พริก" (ไม่เกิน 100 ตัวอักษร) แสดงตัวแดงในหน้าจอครัว |
| `round_no` | SMALLINT | **รอบการสั่ง** — 1 = รอบแรก, 2+ = สั่งเพิ่มระหว่างทาน |
| `status` | `order_item_status` | `ORDERED` รอทำ / `SERVED` เสิร์ฟแล้ว (กดจากหน้าจอครัว) / `CANCELLED` ยกเลิก |
| `by_customer` | BOOLEAN | `TRUE` = ลูกค้าสั่งเองผ่านมือถือ ใช้นับ "ออเดอร์ใหม่" บนผังร้าน |
| `created_at` | TIMESTAMPTZ | เวลาสั่ง ใช้จับเวลารอในหน้าจอครัว (เตือนที่ 10 / 20 นาที) |

รายการที่ยกเลิกจะเปลี่ยนเป็น `CANCELLED` แทนการลบ เพื่อให้ตรวจสอบย้อนหลังได้

### `payments` — การชำระเงิน

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `order_id` | FK → `orders` | บิล (หนึ่งบิลชำระหลายครั้งได้) |
| `method` | `payment_method` | `CASH` เงินสด / `TRANSFER` โอนเงิน / `QR` QR Code |
| `amount` | NUMERIC(12,2) | ยอดที่รับชำระ |
| `received` / `change_amount` | NUMERIC(12,2) | เงินที่รับมาและเงินทอน (เฉพาะเงินสด) |
| `reference_no` | VARCHAR(60) | เลขอ้างอิงการโอน/สลิป |
| `receipt_no` | VARCHAR(24) UNIQUE | เลขที่ใบเสร็จ รูปแบบ `RC20260827-0001` |
| `cashier_id` | FK → `users` | พนักงานที่รับเงิน |
| `paid_at` | TIMESTAMPTZ | เวลารับเงิน (รายงานช่องทางชำระเงินใช้คอลัมน์นี้) |

## ตารางคลังวัตถุดิบ

### `stock_docs` / `stock_doc_lines` — เอกสารรับเข้าและเบิกใช้

| ตาราง | คอลัมน์ | คำอธิบาย |
|---|---|---|
| `stock_docs` | `doc_no` | เลขเอกสาร `IN20260827-0001` รับเข้า / `IS20260827-0001` เบิกใช้ |
| | `doc_type` | `stock_doc_type`: `IN` / `ISSUE` |
| | `doc_date` `supplier` `note` | วันที่เอกสาร ผู้จำหน่าย หมายเหตุ |
| | `total_cost` | มูลค่ารวมของเอกสาร |
| | `created_by` | FK → `users` ผู้บันทึก |
| `stock_doc_lines` | `doc_id` | FK → `stock_docs` |
| | `ingredient_id` | FK → `ingredients` |
| | `qty` `unit_cost` `line_cost` `note` | จำนวน ต้นทุนต่อหน่วย มูลค่าบรรทัด หมายเหตุ |

ทุกบรรทัดของเอกสารสร้าง `stock_movements` 1 รายการเสมอ

### `stock_movements` — บัญชีเดินสะพัดวัตถุดิบ

**ตารางสำคัญที่สุดของฝั่งสต็อก** — ทุกการเคลื่อนไหวของวัตถุดิบถูกบันทึกที่นี่โดยไม่มีข้อยกเว้น

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `ingredient_id` | FK → `ingredients` | วัตถุดิบ |
| `movement_type` | `movement_type` | `IN` รับเข้า / `ISSUE` เบิกใช้ / `SALE` ตัดจากการขาย / `RETURN` คืนสต็อก / `ADJUST` ปรับยอด |
| `qty_change` | NUMERIC(12,3) | จำนวนที่เปลี่ยน (+ เข้า / − ออก) |
| `balance_after` | NUMERIC(12,3) | ยอดคงเหลือหลังทำรายการ — ทำให้ตรวจย้อนหลังได้ว่ายอด ณ เวลาใดเป็นเท่าไร |
| `unit_cost` | NUMERIC(12,2) | ต้นทุนต่อหน่วย ณ ตอนทำรายการ (ใช้คิดมูลค่ารับเข้า) |
| `ref_type` / `ref_id` / `ref_no` | | อ้างอิงกลับไปยังบิลหรือเอกสารต้นทาง (`ORDER` / `STOCK_DOC` / `MANUAL`) |
| `note` | TEXT | คำอธิบาย เช่น "ขาย ชุดหมูกระทะ x1", "ยอดตั้งต้นตอนเพิ่มวัตถุดิบใหม่" |
| `created_by` | FK → `users` | ผู้ทำรายการ (เป็น NULL เมื่อลูกค้าสั่งเอง) |

การปรับยอดจากการนับ (`ADJUST`) ล็อกแถววัตถุดิบก่อนคำนวณส่วนต่าง ยอดหลังปรับจึงตรงกับที่นับได้แม้มีการขายพร้อมกัน

## ตั้งค่าร้าน

### `settings` — ค่าตั้งค่าแบบคีย์-ค่า

| คอลัมน์ | ชนิด | คำอธิบาย |
|---|---|---|
| `key` | TEXT PK | ชื่อค่าตั้งค่า |
| `value` | TEXT | ค่า (เก็บเป็นข้อความ ระบบแปลงเป็นตัวเลข/true-false ตอนใช้) |
| `description` | TEXT | คำอธิบาย |

| key | ใช้ทำอะไร | ค่าที่ยอมรับ |
|---|---|---|
| `shop_name` `shop_branch` `shop_address` `shop_phone` | ข้อมูลร้านบนใบเสร็จ / ใบ QR | ข้อความ (`shop_name` ห้ามว่าง) |
| `shop_taxid` | เลขผู้เสียภาษีบนใบเสร็จ | ตัวเลข 13 หลัก หรือว่าง |
| `vat_rate` / `service_rate` | ภาษีมูลค่าเพิ่ม / ค่าบริการ (%) | ตัวเลข 0–100 |
| `vat_included` | ราคาขายรวม VAT แล้วหรือไม่ | `true` / `false` |
| `promptpay_id` | พร้อมเพย์สำหรับสร้าง QR รับเงิน | เบอร์มือถือ 10 หลัก หรือเลขผู้เสียภาษี 13 หลัก |
| `low_stock_alert` | เปิดการแจ้งเตือนวัตถุดิบใกล้หมด | `true` / `false` |
| `customer_base_url` | ที่อยู่เว็บที่ใส่ใน QR ให้ลูกค้าเปิด (เช่นลิงก์ Cloudflare) | `http(s)://…` หรือว่าง |

`PATCH /api/settings` ตรวจค่าทุกตัวตามตารางนี้ก่อนบันทึก ผิดข้อเดียวไม่บันทึกเลยสักค่า และไม่รับ key ที่ระบบไม่รู้จัก

## View สำหรับการสืบค้น

| View | ใช้ทำอะไร |
|---|---|
| `v_table_status` | ผังสถานะโต๊ะ 20 โต๊ะ พร้อมยอดเงินคงค้าง จำนวนรายการ เวลาเช็คบิล (`billing_at`) และจำนวนออเดอร์ใหม่จากลูกค้า (`new_items`) ของแต่ละโต๊ะ |

## กติกาความถูกต้องที่บังคับในระบบ

นอกจากข้อบังคับในฐานข้อมูล (UNIQUE / CHECK / FK / ENUM) backend บังคับกติกาเหล่านี้ภายในทรานแซกชันเดียวกับการบันทึก:

| กติกา | ผลเมื่อฝ่าฝืน |
|---|---|
| เลขเอกสาร (`OD` / `RC` / `IN` / `IS`) ออกทีละรายการด้วย `pg_advisory_xact_lock` ต่อชนิดเอกสารต่อวัน | ไม่เกิดเลขซ้ำแม้เปิดบิลหลายโต๊ะพร้อมกัน |
| ยอดบิล (`grand_total`) ต้องไม่ต่ำกว่าเงินที่รับไว้แล้ว (`SUM(payments.amount)`) | ลดจำนวน / ยกเลิกรายการ / ให้ส่วนลด ถูกปฏิเสธ (409) |
| บิลที่รับเงินไปแล้วยกเลิกทั้งบิล (`VOID`) ไม่ได้ | 409 — ให้ยกเลิกเฉพาะรายการแล้วปิดบิล |
| `discount` ต้องไม่เกิน `subtotal` | 400 · ถ้ายอดรวมลดลงทีหลัง ระบบปรับส่วนลดลงให้เท่ายอดรวม |
| ตัดสต็อกได้เฉพาะเมื่อวัตถุดิบพอ (ล็อกแถวด้วย `FOR UPDATE`) | 409 พร้อมบอกวัตถุดิบที่ขาด |
| ผู้ใช้ต้อง `is_active` และ token ต้องออกหลังเปลี่ยนรหัสผ่านล่าสุด (ตรวจทุกคำขอ) | 401 ทันทีเมื่อปิดบัญชีหรือเปลี่ยนรหัสผ่าน · เปลี่ยน `role` มีผลทันที |

## ชนิดข้อมูลที่นิยามเอง (ENUM)

```sql
user_role         : OWNER, STAFF
table_status      : FREE, OCCUPIED, BILLING
order_status      : OPEN, BILLING, PAID, VOID
order_item_status : ORDERED, SERVED, CANCELLED
order_channel     : STAFF, CUSTOMER
payment_method    : CASH, TRANSFER, QR
ingredient_group  : MEAT, VEGETABLE, DRINK, ICE, OTHER
movement_type     : IN, ISSUE, SALE, RETURN, ADJUST
stock_doc_type    : IN, ISSUE
```

การใช้ ENUM แทนข้อความอิสระทำให้ฐานข้อมูลปฏิเสธค่าที่ไม่ถูกต้องตั้งแต่ชั้นล่างสุด
