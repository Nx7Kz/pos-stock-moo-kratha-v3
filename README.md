# ระบบจัดการร้านย่างให้หมูกระทะ บ้านน้องโฟค กาญจนบุรี

**Module :** การจัดการการขายหน้าร้านและการตัดสต็อกวัตถุดิบ (POS & Inventory Management)

**Programmer :** นายพงศพัทธ์ ดวงจิตต์ · นายอริญชัย สุวรรณเกิด · นางสาวแสงรัส จองดี

ระบบรับออเดอร์หน้าร้านแบบ A La Carte สำหรับโต๊ะ 20 โต๊ะ ชำระเงินด้วยเงินสด / โอนเงิน / QR Code
ออกใบเสร็จรับเงิน และ **ตัดสต็อกวัตถุดิบอัตโนมัติตามสูตรอาหาร (BOM) ทันทีที่บันทึกการขาย**
พร้อมแจ้งเตือนวัตถุดิบใกล้หมด และรายงานยอดขาย/สต็อกที่ส่งออกเป็น Excel หรือพิมพ์เป็น PDF ได้

ลูกค้า**สแกน QR ที่โต๊ะแล้วสั่งอาหารเองจากมือถือ** (กรอกรหัสโต๊ะ 4 หลักที่ได้ตอนเปิดโต๊ะ) สั่งกี่รอบก็ได้
แล้วค่อยไปชำระเงินที่เคาน์เตอร์ ออเดอร์ขึ้น**หน้าจอครัว**ทันที และหน้าร้านมีเสียงเตือนเมื่อลูกค้าสั่งเข้ามา

## เริ่มใช้งาน

### 1. เปิดฐานข้อมูล PostgreSQL

ต้องเปิดโปรแกรม **Docker Desktop** ก่อน แล้วรัน

```bash
docker compose up -d db
```

ฐานข้อมูลจะขึ้นที่ `localhost:5432` — ชื่อฐานข้อมูล `pos_stock` ผู้ใช้ `pos_admin` รหัสผ่าน `pos_pass123`

> อยากดูข้อมูลผ่านหน้าเว็บ ให้รัน `docker compose up -d` (ขึ้นทั้ง db และ pgAdmin) แล้วเปิด http://localhost:5050
> เซิร์ฟเวอร์ฐานข้อมูลถูกลงทะเบียนไว้ให้อัตโนมัติแล้ว คลิกที่ชื่อ **POS & Stock** แล้วใส่รหัสผ่าน `pos_pass123`

### 2. สร้างตารางและข้อมูลตั้งต้น

```bash
cd backend && npm install && npm run db:migrate
```

> `db:migrate` ใช้ติดตั้งครั้งแรก ถ้าฐานข้อมูลมีข้อมูลอยู่แล้วจะ**หยุดโดยไม่ลบอะไร** (กันเผลอรันทับร้านที่ใช้งานจริง)
>
> ต้องการล้างข้อมูลทั้งหมดแล้วเริ่มใหม่จริง ๆ ให้ใช้ `npm run db:reset` ระบบจะให้พิมพ์ชื่อฐานข้อมูลยืนยันก่อน
> (รันจากสคริปต์ที่ไม่มีหน้าจอให้พิมพ์ ให้ตั้ง `CONFIRM_RESET=pos_stock`)
> ⚠️ บิล สต็อก และรหัสผ่านที่เปลี่ยนไว้จะหายทั้งหมด กู้คืนไม่ได้ถ้าไม่มีไฟล์สำรอง

### 3. เปิด Back end

```bash
cd backend && npm run dev       # รีสตาร์ตเองเมื่อแก้โค้ด (ใช้งานจริงใช้ npm start)
```

ตรวจว่าทำงาน: เปิด http://localhost:4000/api/health

### 4. เปิด Front end

```bash
cd frontend && npm install && npm run dev
```

เปิด http://localhost:5173 — มือถือที่ต่อ WiFi เดียวกับร้านเปิดผ่าน IP ของเครื่องได้ เช่น `http://192.168.1.108:5173`

### 5. (ถ้าต้องการ) เปิดให้ลูกค้าใช้เน็ตมือถือสั่งอาหารได้ ด้วย Cloudflare Tunnel

```bash
cd frontend && npm run build            # backend จะเสิร์ฟหน้าเว็บจาก frontend/dist ที่พอร์ต 4000
cloudflared tunnel --url http://localhost:4000
```

นำลิงก์ `https://….trycloudflare.com` ที่ได้ไปใส่ที่ **⚙ ตั้งค่าที่อยู่เว็บใน QR** (อยู่ในหน้าต่าง QR ตอนเปิดโต๊ะ ใช้บัญชีเจ้าของร้าน) แล้วกดบันทึก

> ลิงก์แบบ quick tunnel **เปลี่ยนทุกครั้งที่เปิด tunnel ใหม่** — ปิดเปิดระบบแล้วต้องใส่ลิงก์ใหม่
> และพิมพ์ใบ QR ของโต๊ะที่เปิดค้างอยู่ใหม่ (รหัส 4 หลักยังเป็นเลขเดิม) ถ้าต้องการลิงก์ถาวรต้องผูกกับโดเมนของร้าน
>
> ก่อนเปิดออกอินเทอร์เน็ต ต้องสร้าง `backend/.env` (คัดลอกจาก `.env.example`) ตั้ง `JWT_SECRET` เอง
> และเปลี่ยนรหัสผ่านบัญชีเริ่มต้นทุกบัญชี

### บัญชีสำหรับเข้าสู่ระบบ

| ผู้ใช้ | รหัสผ่าน | สิทธิ์ | ใช้ทำอะไรได้ |
|---|---|---|---|
| `owner` | `owner123` | เจ้าของร้าน | ทุกเมนู รวมถึงแก้เมนู รูปเมนู สูตร BOM ปรับยอดสต็อก และตั้งที่อยู่เว็บใน QR |
| `arin` | `staff123` | เจ้าของร้าน | เหมือน `owner` |
| `staff1`, `staff2` | `staff123` | พนักงาน | เปิดโต๊ะ สั่งอาหาร หน้าจอครัว ชำระเงิน รับเข้า/เบิกใช้วัตถุดิบ |

> **รหัสผ่านทั้งหมดในเอกสารนี้เป็นค่าสำหรับทดลองบนเครื่องตัวเองเท่านั้น**
> ทั้งรหัสผู้ใช้ รหัสฐานข้อมูล (`pos_pass123`) และรหัส pgAdmin (`admin1234`)
> ถ้าจะนำระบบขึ้นใช้งานจริงหรือเปิดให้เข้าถึงจากเครือข่ายภายนอก ต้องเปลี่ยนทั้งหมดก่อน
> และต้องสร้างไฟล์ `backend/.env` กำหนด `JWT_SECRET` ของตัวเอง
> (ถ้าตั้ง `NODE_ENV=production` โดยไม่กำหนด `JWT_SECRET` เซิร์ฟเวอร์จะไม่ยอมเริ่มทำงาน
> เพื่อกันไม่ให้ใครปลอม token เป็นเจ้าของร้านจากค่าเริ่มต้นที่เห็นได้ในโค้ด)

### ข้อมูลตัวอย่างสำหรับดูรายงาน (ไม่บังคับ)

```bash
cd backend && npm run db:demo
```

สร้างยอดขายย้อนหลัง 45 วัน (~600 บิล) เพื่อให้หน้ารายงานมีข้อมูลจริงให้ดู

### สำรองและคืนค่าข้อมูลร้าน

ข้อมูลการขาย สต็อก และบัญชีผู้ใช้อยู่ในฐานข้อมูลของเครื่องนี้เท่านั้น **ไม่ได้ขึ้น GitHub** จึงต้องสำรองเอง
(ต้องเปิด Docker และฐานข้อมูลไว้)

```bash
cd backend
npm run db:backup                        # สำรองตอนนี้ -> backend/backups/<วันที่_เวลา>/
npm run db:restore                       # ดูรายการไฟล์สำรองที่มี
npm run db:restore -- latest             # คืนค่าจากชุดล่าสุด
npm run db:restore -- 2026-09-24_164852  # คืนค่าจากชุดที่ระบุ
```

- ไฟล์สำรอง 1 ชุด = ฐานข้อมูลทั้งหมด (บิล สต็อก ผู้ใช้/รหัสผ่าน ตั้งค่า) + รูปเมนูที่อัปโหลด + `info.txt` สรุปข้อมูล
- ระบบตรวจว่าไฟล์สำรองอ่านกลับได้จริงทุกครั้ง และเก็บย้อนหลัง 30 ชุดล่าสุด (ตั้ง `BACKUP_KEEP` ใน `.env` ได้)
- คืนค่าต้องพิมพ์ชื่อฐานข้อมูลยืนยัน และระบบจะ**สำรองข้อมูลปัจจุบันให้ก่อนอัตโนมัติ** (`…_before-restore`) คืนผิดชุดก็ย้อนกลับได้
- ย้ายเครื่อง: clone + ติดตั้งตามขั้นตอนด้านบน แล้วคัดลอกโฟลเดอร์สำรองมาไว้ใน `backend/backups/` แล้ว `npm run db:restore -- latest`
- ⚠️ **ควรเก็บสำเนาไว้นอกเครื่องด้วย** (OneDrive / Google Drive / แฟลชไดรฟ์) — ตั้ง `BACKUP_DIR` ใน `.env` ให้ชี้ไปโฟลเดอร์ที่ซิงก์ขึ้นคลาวด์ได้
- ไฟล์สำรองมีข้อมูลการขายและรหัสผ่าน (เข้ารหัสแล้ว) ห้ามขึ้น GitHub (`backend/backups/` อยู่ใน `.gitignore` แล้ว)

### หน้าตาและการใช้งาน

- **ธีมร้าน:** โทนแดงตามโลโก้ + ถ่าน ฟอนต์หัวข้อ Kanit มีโลโก้ในหน้าเข้าสู่ระบบ เมนูซ้าย และหัวหน้าลูกค้า
- **โหมดมืด:** ค่าเริ่มต้นตามการตั้งค่าของเครื่อง สลับเองได้ด้วยปุ่ม 🌙 / ☀ (เมนูซ้ายฝั่งร้าน และแถบหัวฝั่งลูกค้า) ใบเสร็จและใบ QR เป็นพื้นขาวเสมอ
- **แท็บเล็ต:** พับเมนูซ้ายเหลือแถบไอคอนได้ (จอกว้างไม่เกิน 1180px เริ่มแบบพับ)
- **ระหว่างโหลดข้อมูล:** แสดงกล่องเทาจำลองหน้าตา (skeleton) แทนข้อความ
- **หน้าต่างยืนยัน:** ใช้หน้าต่างของระบบแทนกล่อง `confirm()` ของเบราว์เซอร์

## ทดสอบผ่าน Postman

1. เปิด Postman → **Import** → เลือกสองไฟล์ในโฟลเดอร์ `postman/`
   - `POS-Stock.postman_collection.json` (80 requests)
   - `POS-Stock.postman_environment.json`
2. เลือก Environment มุมขวาบนเป็น **POS & Stock — Local**
3. รัน `1. Authentication → เข้าสู่ระบบ (เจ้าของร้าน)` ก่อน — token จะถูกเก็บลง `{{token}}` อัตโนมัติ
4. จากนั้นเรียก request อื่นได้เลย หรือกด **Run collection** เพื่อทดสอบทั้งชุดตามลำดับจริง

โฟลเดอร์ `5. ขายหน้าร้าน — Flow หลัก` ออกแบบให้รันเรียงกันตั้งแต่เปิดบิล → สั่งอาหาร →
ตรวจว่าตัดสต็อกจริง → สั่งเพิ่ม → เช็คบิล → QR → ชำระเงิน → ใบเสร็จ

รันจากบรรทัดคำสั่งก็ได้:

```bash
npx newman run postman/POS-Stock.postman_collection.json -e postman/POS-Stock.postman_environment.json
```

> **ก่อนกด Run collection ให้รันบนฐานข้อมูลที่สะอาด (ฐานข้อมูลใหม่ หรือหลัง `npm run db:reset`) ทุกครั้ง**
> เพราะ test script ตรวจตัวเลขสต็อกและยอดเงินแบบเป๊ะ ๆ (เช่น "หมูสไลซ์ต้องลดลง 0.8 กก. พอดี")
> ถ้าฐานข้อมูลมีการขายค้างอยู่ ตัวเลขจะไม่ตรงและ assertion จะไม่ผ่าน
> ด้วยเหตุผลเดียวกัน อย่ารัน `npm test` กับ Postman ต่อกันโดยไม่ล้างฐานข้อมูลระหว่างกลาง
> **ห้ามรันกับฐานข้อมูลของร้านที่ใช้งานจริง** — ใช้ฐานข้อมูลแยกสำหรับทดสอบ (ดูหัวข้อ "การทดสอบ")

## หลักการทำงานที่สำคัญ

### การตัดสต็อกตามสูตรอาหาร (BOM)

เมนูแต่ละรายการผูกกับวัตถุดิบผ่านตาราง `recipes` เช่น *ชุดหมูกระทะเซ็ตกลาง 4 ท่าน* ใช้หมูสไลซ์
0.8 กก. เนื้อวัว 0.3 กก. ผักกาดขาว 0.8 กก. ฯลฯ

เมื่อบันทึกรายการอาหารเข้าบิล ระบบจะ**ตัดสต็อกทันทีในทรานแซกชันเดียวกัน**:

1. ตรวจก่อนว่าวัตถุดิบพอหรือไม่ — ถ้าไม่พอจะปฏิเสธพร้อมบอกว่าขาดอะไร (HTTP 409)
2. ล็อกแถววัตถุดิบด้วย `SELECT … FOR UPDATE` กันยอดเพี้ยนเมื่อหลายโต๊ะสั่งพร้อมกัน
3. หักยอดคงเหลือ แล้วเขียนบรรทัดลง `stock_movements` ทุกครั้ง (บัญชีเดินสะพัด ตรวจย้อนหลังได้เสมอ)
4. ถ้ายอดคงเหลือหลังตัดต่ำกว่าจุดสั่งซื้อขั้นต่ำ จะส่ง `stock_alerts` กลับมาให้หน้าจอแจ้งเตือน

การยกเลิกรายการหรือยกเลิกทั้งบิลจะ **คืนวัตถุดิบกลับคลังอัตโนมัติ** (movement ประเภท `RETURN`)

### สถานะโต๊ะ

`FREE` ว่าง → `OCCUPIED` กำลังใช้งาน (มีบิลเปิดอยู่) → `BILLING` รอชำระเงิน → กลับเป็น `FREE` เมื่อปิดบิล

ฐานข้อมูลบังคับด้วย partial unique index ว่า **หนึ่งโต๊ะเปิดบิลค้างได้ครั้งละ 1 ใบเท่านั้น**

### การสั่งเพิ่มระหว่างทาน

รายการอาหารเก็บ `round_no` แยกรอบ ทำให้หน้าจอแสดงเป็น "รอบแรก / สั่งเพิ่มรอบที่ 2 …" ได้
และตรวจสอบย้อนหลังได้ว่าลูกค้าสั่งอะไรเพิ่มตอนไหน

### ฝั่งลูกค้าสั่งเอง

1. พนักงานกด **เปิดโต๊ะ + ออก QR** บนผังร้าน ระบบสุ่มรหัสโต๊ะ 4 หลักให้บิลนั้น แล้วพิมพ์ใบ QR ไปวางที่โต๊ะ
2. ลูกค้าสแกน QR แล้วกรอกรหัส 4 หลักจากใบ QR (QR ไม่ฝังรหัส กันคนถ่ายรูป QR ไปสั่งทีหลัง)
   จากนั้นสั่งกี่รอบก็ได้ ยังไม่ต้องจ่าย
3. ออเดอร์ขึ้นหน้าจอครัวทันที และหน้าผังร้านมีเสียงเตือน + ป้าย 🔔 ออเดอร์ใหม่ จนกว่าพนักงานจะเปิดดูบิล
4. ลูกค้ากด **เช็คบิล** แล้วไปชำระเงินที่เคาน์เตอร์ — โต๊ะขึ้นแถบ "รอชำระเงิน" บนผังร้าน
5. ปิดบิลแล้วรหัสเดิมใช้ไม่ได้ทันที ลูกค้าโต๊ะก่อนหน้าจึงสั่งกวนไม่ได้
   (กรอกรหัสผิดเกิน 10 ครั้งใน 10 นาที ระบบจะให้รอก่อน)

มือถือลูกค้าต้องเปิดที่อยู่เว็บใน QR ได้ — ต่อ WiFi เดียวกับร้าน หรือเปิดผ่าน Cloudflare Tunnel
ตั้งที่อยู่นี้ได้ที่ **⚙ ตั้งค่าที่อยู่เว็บใน QR** ในหน้าต่าง QR ตอนเปิดโต๊ะ

### รูปเมนู

- ติดตั้งใหม่ทุกเมนูมี**รูปตัวอย่าง**จาก Wikimedia Commons (`backend/media/samples/` เครดิตผู้สร้างรูปอยู่ใน `CREDITS.md`)
- เจ้าของร้านอัปโหลดรูปจริงแทนได้ที่หน้า **จัดการเมนู** ระบบย่อรูปในเบราว์เซอร์ก่อนส่ง ถ่ายจากมือถือได้เลย
- รูปที่อัปโหลดเก็บที่ `backend/media/uploads/` **ชื่อไฟล์ตามรหัสเมนู** (เช่น `mn-b04.jpg`) และขึ้น git ด้วย
  ตอนเปิดระบบ เมนูที่มีไฟล์ในโฟลเดอร์นี้จะใช้รูปนั้นอัตโนมัติ — clone ไปเครื่องใหม่ก็เห็นรูปที่ร้านอัปโหลดไว้
- เมนูที่ไม่มีรูป (หรือโหลดรูปไม่ได้) แสดงไอคอนของหมวดแทน

## รายงานที่มีในระบบ

| รายงาน | ปลายทาง | ส่งออก |
|---|---|---|
| ยอดขายรายวัน / รายสัปดาห์ / รายเดือน | `GET /api/reports/sales?group=day\|week\|month` | CSV, พิมพ์ |
| อันดับเมนูขายดี | `GET /api/reports/top-menu` | CSV, พิมพ์ |
| วัตถุดิบคงเหลือ | `GET /api/reports/stock` | CSV, พิมพ์ |
| วัตถุดิบใกล้หมด (Low Stock Alert) | `GET /api/reports/stock?only_low=true` | CSV, พิมพ์ |
| การรับเข้าและเบิกใช้วัตถุดิบ | `GET /api/reports/stock-movements` | CSV, พิมพ์ |
| บิลขายรายใบ | `GET /api/reports/bills` | CSV, พิมพ์ |
| สัดส่วนช่องทางชำระเงิน | `GET /api/reports/payment-methods` | CSV |

ทุกรายงานเติม `?format=csv` เพื่อดาวน์โหลดไฟล์เปิดใน **MS-Excel** ได้ (ไฟล์มี BOM ให้อ่านภาษาไทยถูกต้อง)
ส่วน **PDF** ใช้ปุ่ม "พิมพ์ / PDF" บนหน้าเว็บแล้วเลือกปลายทางเป็น *Save as PDF*

## การทดสอบ

```bash
cd backend && npm test          # ชุดทดสอบ 167 รายการ ครอบคลุมทั้งระบบ
```

ชุดทดสอบตรวจตัวเลขสต็อกแบบเป๊ะ ๆ จึงต้องรันกับฐานข้อมูลที่สะอาด
**ถ้าร้านใช้งานจริงอยู่ ให้ทดสอบกับฐานข้อมูลแยก** ไม่ต้องล้างข้อมูลร้าน:

```bash
# สร้างฐานข้อมูลทดสอบ แล้วเปิด back end อีกตัวที่พอร์ต 4001
docker exec pos_stock_db psql -U pos_admin -d postgres -c "CREATE DATABASE pos_stock_test"
cd backend
PGDATABASE=pos_stock_test npm run db:migrate
PGDATABASE=pos_stock_test PORT=4001 node src/server.js &
API_BASE=http://localhost:4001/api npm test
# เสร็จแล้วปิด back end ตัวที่ 4001 และลบฐานข้อมูล pos_stock_test ทิ้งได้
```
